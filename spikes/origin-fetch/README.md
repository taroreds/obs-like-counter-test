# origin / CORS 診断スパイク

## 1. 目的

このスパイクは、現在のoriginから `https://www.googleapis.com` へfetchできるかを確認するための診断ツールです。

`docs/decisions.md` D-034 の確認対象「file:// origin から googleapis.com へfetchできるか」に対応します。この結果は D-032（設定支援クライアントか、管理アプリ＋ローカルWebサーバーか）の判断材料になります。

## 2. 製品本体との関係

このフォルダのファイルは技術検証専用です。製品本体には組み込みません。

このスパイクの結果がどうであっても、API連携の実装方針は別途決定します。

## 3. APIキーについて

有効なAPIキーは不要です。無効なキーを使用します。

判定に必要なのは次の区別だけです。

* fetchがレスポンスを返した（HTTPステータスが400でも構いません）→ CORSは通過しています
* fetchがTypeErrorで失敗した → CORSで遮断された可能性があります

このファイルへ有効なAPIキーを書き込まないでください。

## 4. 判定の対応表

| 診断1（通常のfetch） | 診断2（no-cors） | 解釈 |
| --- | --- | --- |
| 成功 | 成功 | CORSは通過する。ブラウザ内でのAPI取得は成立しうる |
| 失敗 | 成功 | ネットワークは到達している。CORSで遮断されている |
| 失敗 | 失敗 | ネットワーク到達自体に問題がある。CORSの判定はできない |

診断1が失敗した場合、その原因がCORSかどうかを画面から断定することはできません。ブラウザの開発者ツールのコンソールに、CORS関連のメッセージが出ていないかもあわせて確認してください。OBSのBrowser Sourceでは開発者ツールを開けないため、この確認は通常ブラウザでのみ可能です。

## 5. 通常ブラウザでの手順

1. `probe.html` をfile URLで開きます。
2. `location.origin` を記録します。
3. 「診断を実行」を押します。

読み込みから2秒後に自動実行されるため、ボタンを押す前に結果が出ている場合があります。ボタンはいつでも再実行に使えます。

4. 診断1と診断2の結果、およびログを記録します。
5. 開発者ツールのコンソールを開き、CORS関連のメッセージがあれば記録します。

## 6. Live Serverを使った対照試験

この製品の要件ではなく、file URLとの差を確認するための対照環境です。

1. `spikes/origin-fetch` をローカルWebサーバーから公開します。
2. `probe.html` を開き、`location.origin` が `http://` で始まることを確認します。
3. 同じ手順で診断を実行し、結果を記録します。

file URLで失敗し、この対照試験で成功する場合、原因はoriginの種類にあると判断できます。

## 7. OBS Browser Sourceでの手順

読み込みから2秒後に診断が自動実行されるため、Browser Sourceでもボタン操作なしで結果を得られます。

ソースを右クリックして「インタラクト」を選ぶと等倍のウィンドウが開き、値の読み取りとボタンによる再実行ができます。プレビューの縮小表示では `location.href` を読み取れないため、値の確認にはインタラクトを使ってください。

インタラクトウィンドウでは値の選択・コピーができない場合があります。その際は手入力するか、スクリーンショットを撮ってください。

`docs/decisions.md` D-011 により、Browser Sourceの登録方法によって実行コンテキストが変わる可能性があります。両方の構成で確認してください。

### 構成A：「ローカルファイル」を有効

1. ブラウザソースを追加し、「ローカルファイル」のチェックを入れます。
2. `spikes/origin-fetch/probe.html` を選択します。
3. 幅1920、高さ1080を指定します。
4. 表示された `location.origin` と診断結果を記録します。

### 構成B：「ローカルファイル」を無効

1. ブラウザソースを追加し、「ローカルファイル」のチェックを外します。
2. URL欄へ `probe.html` のfile URLを入力します。
3. 幅1920、高さ1080を指定します。
4. 表示された `location.origin` と診断結果を記録します。

## 8. OBSカスタムブラウザドックでの手順

1. 「表示」メニューから「ドック」→「カスタムブラウザドック」を開きます。
2. URL欄へ `probe.html` のfile URLを入力します。
3. ドックではボタンを押せるため、自動実行を待たずに「診断を実行」で再実行できます。
4. `location.origin` と診断結果を記録します。

## 10. この結果が影響する決定

* D-034（YouTube Data APIスパイク）の実行可能性
* D-032（管理アプリ方式のA案とB案の選択）

CORSが遮断される場合、A案（設定支援クライアント）はブラウザ内でのAPI自動取得を成立させられません。

2026-08-02 の測定でCORSは通過することが確認された。したがってA案（設定支援クライアント）はブラウザ内でのAPI自動取得を成立させられる。A案とB案の選択は技術的制約ではなく商品判断に移った。
