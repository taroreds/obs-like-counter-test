# テスト計画

## 1. 目的

この文書は、OBSブラウザソース用ウィジェットの手動テスト項目と期待結果を定義するものです。

現段階では、次の品質を確認します。

* ローカルファイルとして正常に読み込めること
* OBS Studioのブラウザソースで正常に表示できること
* 設定値が不正でも表示全体が停止しないこと
* テーマ、配置、サイズが仕様どおり切り替わること
* 現在値、目標値、進捗率が正しく表示されること
* 長文や特殊文字でも実用可能な表示を維持すること
* 今後追加する状態管理や入力処理が既存表示を破壊しないこと

外部API、ネットワーク通信、OBS WebSocketなどは、実装するまで対象外とします。

## 2. テスト環境

### 2.1 主環境

* デスクトップPC
* Windows
* OBS Studio
* ローカルの `index.html` をブラウザソースとして使用
* 基本キャンバス解像度：1920×1080
* 出力解像度：1920×1080
* フレームレート：30 FPS

### 2.2 副環境

* ノートPC
* Windows
* OBS Studio
* ローカルの `index.html` をブラウザソースとして使用

副環境では、主に次を確認します。

* 別PCでも同じ手順で表示できること
* 相対パスによるファイル参照が成立すること
* 主環境固有の設定やソフトウェアに依存していないこと
* 表示負荷に大きな問題がないこと

### 2.3 クリーン環境

必要に応じて、仮想環境または新規Windowsユーザー環境を使用します。

確認対象は次のとおりです。

* ZIPファイルを展開しただけで利用できること
* ファイル間の相対参照が成立すること
* 未申告の依存関係がないこと
* READMEの手順だけで導入できること

仮想環境でのGPU負荷は、実機性能の判定根拠にはしません。

## 3. 基本読み込みテスト

### T-001：通常ブラウザでの読み込み

#### 手順

1. デスクトップブラウザで `index.html` を開く。
2. ウィジェットの表示を確認する。
3. ブラウザの開発者ツールで、重大なJavaScriptエラーがないことを確認する。

#### 期待結果

* 画面が空白にならない。
* CSSが適用される。
* ラベル、現在値、目標値、進捗バー、メッセージが表示される。
* `undefined`、`null`、`NaN`、`Infinity` が文字として表示されない。
* ファイル不足を示すエラーが発生しない。

### T-002：OBSでのローカルファイル読み込み

#### 手順

1. OBSで検証用シーンを開く。
2. `index.html` をブラウザソースとして追加する。
3. 「ローカルファイル」を有効にする。
4. ブラウザソースの幅を1920、高さを1080に設定する。
5. ブラウザソースを更新する。

#### 期待結果

* ページ背景が透明になる。
* 背景ソースの上にウィジェットが表示される。
* ウィジェット以外の領域が黒または白で塗りつぶされない。
* シーンを切り替えて戻っても表示される。

### T-003：OBS再起動

#### 手順

1. ブラウザソースが正常に表示されていることを確認する。
2. OBSを終了する。
3. OBSを再起動する。
4. 検証用プロファイルとシーンコレクションを開く。

#### 期待結果

* ブラウザソースを再設定せず表示される。
* ファイルパスが維持される。
* テーマ、配置、サイズが設定どおり反映される。

### T-004：ブラウザソース更新

#### 手順

1. `config.js` の表示内容を変更して保存する。
2. OBS上でブラウザソースを更新する。

#### 期待結果

* 変更内容が反映される。
* OBS自体の再起動を必要としない。
* 更新後も表示構造が破綻しない。

### T-005：シーン切替

#### 手順

1. ウィジェットを表示したシーンを開く。
2. 別のシーンへ切り替える。
3. 元のシーンへ戻る。
4. この操作を複数回繰り返す。

#### 期待結果

* 元のシーンへ戻るたびに正常に表示される。
* ウィジェットが重複しない。
* 表示位置が変化しない。
* 処理負荷が継続的に増加しない。

* 操作パネルの表示処理とウィジェットの描画処理が分離されている。
* 不正な入力値は状態管理層で拒否または補正される。

### T-205：file URLでの通常ブラウザ通信

#### 手順

1. `index.html` と `controller.html` を同じ配布フォルダからfile URLで開く。
2. controllerが「同期済み」になることを確認する。
3. controllerから増減操作を行う。

#### 期待結果

* controllerの現在値と目標値が表示側の値と一致する。
* 表示側の進捗バーが状態変更に応じて更新される。
* controllerの最終同期時刻が更新される。

### T-206：controller先行・表示側先行

#### 手順

1. controllerを先に開き、その後に`index.html`を開く。
2. 両方を閉じ、今度は`index.html`を先に開いてcontrollerを開く。

#### 期待結果

* どちらの順序でもcontrollerが「同期済み」になる。
* 同期済みになるまで操作が無効である。

### T-207：controllerの全操作

#### 手順

1. `-10`、`-1`、`+1`、`+10`を順に実行する。
2. 現在値と目標値を直接設定する。
3. カウンターリセットと全体リセットを実行する。

#### 期待結果

* 各操作が1回だけ表示側の状態へ反映される。
* 全体リセットでは確認ダイアログを承認した場合だけアクションが送信される。
* controllerは表示側からstateを受信した時だけ数値表示を更新する。

### T-208：controller直接入力の検証

#### 手順

1. 現在値と目標値に正常値、空文字、不正文字列、負数、小数を入力する。
2. 各入力で設定ボタンを押す。

#### 期待結果

* 空文字、不正文字列、現在値の負数、目標値の1未満はcontroller内にエラー表示される。
* 小数は送信でき、state.jsの仕様に従って小数点以下が切り捨てられる。
* 不正入力で表示側の状態は変更されない。

### T-209：再同期と不正な通信メッセージ

#### 手順

1. controllerの「再同期」を押す。
2. 開発者ツールから未知のkind、不正なaction、actionの配列をチャンネルへ送る。

#### 期待結果

* 再同期後に最新stateを受信して「同期済み」へ戻る。
* 不正な通信メッセージは表示側のdispatchへ渡されず、状態は変わらない。

### T-210：controller再読み込みとBrowser Source更新

#### 手順

1. controllerを再読み込みする。
2. Browser Sourceを更新する。

#### 期待結果

* controller再読み込み後は自動で再同期される。
* Browser Source更新後は実行時状態が初期設定へ戻り、controllerが更新される。

### T-211：OBSでのfile URL通信

#### 手順

1. Browser Sourceの「ローカルファイル」を無効にする。
2. URL欄に`index.html`のfile URLを指定する。
3. カスタムブラウザドックに`controller.html`のfile URLを指定する。
4. シーン切替、OBS再起動、controllerの再同期を確認する。

#### 期待結果

* OBS内で双方向通信と全操作が成立する。
* シーン切替とOBS再起動後の状態初期化または同期挙動が仕様どおりである。
* `window.confirm()`がドックで機能するかを記録する。

### T-212：複数表示ページの非対応確認

#### 手順

## 9. OBS動作テスト

### T-301：ブラウザソース更新後の状態

## 10. 録画確認

表示に影響する変更を行った場合は、OBSで録画確認を実施します。

### 手順

1. 対象シーンを表示する。
2. OBSで約10秒録画する。
3. 録画ファイルを再生する。
4. 表示内容を確認する。

### 確認項目

* 文字の可読性
* 背景の透明性
* 枠線の視認性
* 進捗バーの表示
* 色のにじみ
* 文字の潰れ
* アニメーションの滑らかさ
* 意図しない黒背景または白背景の有無
* フレーム落ちまたは著しい負荷の有無

### 使用する背景

少なくとも次の背景で確認します。

* 黒または暗いネイビー
* 明るいグレー
* 歌枠想定の淡いラベンダー
* ストレステスト用の明るい黄色

## 14. 完了基準

初期試作品の状態管理実装は、次をすべて満たした時点で完了とします。

* 通常ブラウザとOBSの両方で表示できる。
* 有効な設定値が仕様どおり反映される。
* 不正な設定値でも画面全体が停止しない。
* 現在値と目標値が安全な範囲へ正規化される。
* 進捗率が0～100%に制限される。
* 状態変更が状態管理層を通じて行われる。
* 描画処理が状態変更処理から分離される。
* 最低限の回帰テストに合格する。
* OBS上の実機確認結果が記録される。
